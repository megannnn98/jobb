# Контекст: дообучение rubert для модерации отзывов

## Задача
Дообучить `DeepPavlov/rubert-base-cased` для автоматической классификации отзывов на сайте.

**Три класса:** `publish` / `manual_review` / `reject`

## Данные
- Десятки тысяч отзывов в БД
- Метки уже есть (статус модерации от администраторов)
- Дисбаланс: большинство — `publish`
- Текущий файл выгрузки: `aj_reviews_export.tsv`
- Колонки TSV: `id`, `name`, `descr`, `status`, `isfunny`, `is_self_delete`, `is_about_work`, `isPositive`
- Важно: `status=0` в текущей выгрузке не подтверждён как валидная метка reject/manual_review. При строгом разборе по табам все строки с числовым `id` имеют `status=1` или пустой `status`; `status=0` встречается только в битых continuation-строках без числового `id`.
- В TSV есть повреждённые строки/continuation-строки из-за многострочного текста и проблемных кавычек. Для обучения нужно сначала очистить выгрузку или сделать новую корректную выгрузку.
- Новая выгрузка `aj_reviews_export.jsonl` технически корректна: 130482 JSON-записи, одинаковая схема, без битых JSON-строк, `id` всегда int, `descr` всегда строка.
- Но `status` в `aj_reviews_export.jsonl` всегда равен `1`, поэтому файл всё ещё не подходит как supervised датасет для 3-классовой модерации.
- Поле `is_about_work` имеет распределение 108959/21523 и может быть пригодно для отдельной вспомогательной бинарной задачи. `isPositive`, `isfunny`, `is_self_delete` слишком редкие для уверенного обучения без дополнительной разметки/балансировки.

## Ключевые решения
1. **Взвешивание классов** (`compute_class_weight("balanced")`) — иначе модель будет предсказывать всё как `publish`
2. **Метрика — macro F1**, не accuracy (accuracy врёт при дисбалансе)
3. **Порог уверенности** — если `softmax confidence < 0.85`, направлять в `manual_review` независимо от предсказания модели

## Гиперпараметры (стартовые)
- `learning_rate`: 2e-5
- `num_train_epochs`: 4
- `per_device_train_batch_size`: 16
- `warmup_ratio`: 0.1
- `weight_decay`: 0.01
